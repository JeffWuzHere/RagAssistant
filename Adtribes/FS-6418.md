# Knowledge Base Entry: TranslatePress feed outputting wrong language — LiteSpeed Cache and Wordfence disrupting feed generation; fix via cache disable and batch size 100

## 🎯 Executive Summary
**The Issue:** A TranslatePress-based feed was outputting the wrong language (Italian/default instead of the requested translated language) despite the language being correctly set in the feed's General settings.
**The Fix:** Disable the LiteSpeed Cache plugin (and/or Wordfence security plugin), set the feed batch size to 100 in Product Feed > Settings, then refresh the feed 1–3 times via incognito. The caching/security plugins were intercepting the feed generation requests and serving cached (wrong-language) responses.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** TranslatePress feed wrong language, translated feed showing original language, TranslatePress language not applying, feed language wrong after refresh, language set correctly but feed in wrong language, caching plugin breaking feed
>
> **Steps to solve:**
> 1. Confirm the TranslatePress language is correctly set on the feed's **General** tab (see also FS-8411 for WPML, FS-8904 for TranslatePress auto-refresh bug).
> 2. If language setting is correct but feed still outputs wrong language, check for caching or security plugins:
>    - Common culprits: **LiteSpeed Cache**, **WP Rocket**, **Wordfence**
> 3. Temporarily **disable** the caching plugin (and Wordfence if present).
> 4. Go to **Product Feed > Settings** and reduce the **Batch Size** to **100**.
> 5. Refresh the feed **2–3 times** and view the XML output each time via **incognito mode** (to bypass any browser/CDN cache).
> 6. Once the feed is generating correctly, re-enable the caching plugin — but consider excluding the Product Feed plugin's folder from JS/CSS minification and caching rules (see the plugin's documentation for the exclusion path).

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- Caching plugins (especially LiteSpeed Cache) can intercept background feed generation AJAX requests and serve cached responses, causing the feed to generate with stale or wrong-language data.
- Wordfence can block or modify certain HTTP requests made during feed generation, particularly if the generation process uses unusual request patterns.
- Setting batch size to 100 (lower than the default 750) slows down generation but makes each batch request simpler and less likely to be blocked or cached.
- Always test feed output via **incognito** — a regular browser session may display a cached version of the XML.
- After resolving, customers should add the Product Feed upload folder to their caching plugin's exclusion list rather than permanently disabling the cache.
- This is distinct from the FS-8904 TranslatePress language bug — that was a plugin-level issue in v5.0.4 and below. This FS-6418 issue affects v5.0.5+ and is caused by external caching infrastructure.
