# Knowledge Base Entry: Image fallback rules not working — rules apply to the mapped field value, not the attribute name

## 🎯 Executive Summary
**The Issue:** Rules set up to fall back to a default image when a custom ACF image field is empty were not working. The customer was referencing the **attribute name** (e.g., "Main image") in the rule condition, but rules must reference the **mapped source field value** (what appears in the right column of Field Mapping).
**The Fix:** In the Rules, use the same field that is mapped in the **Field Mapping value column** — not the attribute label on the left. If `image_link` is mapped to `feed_image_facebook`, the rule condition must check `feed_image_facebook`, not "Main image."

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** rules not working for images, fallback image rule not triggering, if empty then set attribute not working, ACF field fallback, image_link fallback not applying, rules ignoring empty fields
>
> **Steps to solve:**
> 1. Ask the customer to share a screenshot of both their **Field Mapping** tab and their **Rules** tab.
> 2. In Field Mapping: identify the **value column** (right side) — this is what is actually mapped to the attribute. For example: `image_link → feed_image_facebook`.
> 3. In Rules: the condition "if [X] is empty" must use `feed_image_facebook` (the mapped value field) — NOT the attribute label `image_link` or the product field name "Main image."
> 4. Correct rule structure:
>    - **If:** `feed_image_facebook` → is empty
>    - **Then:** `feed_image_facebook` → Set attribute → `[fallback field or static URL]`
> 5. After correcting the rule, regenerate the feed and verify via incognito that the fallback image is appearing for products where the custom field is empty.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- Enhancement request tracked at: https://github.com/Rymera-Web-Co/woo-product-feed-pro/issues/815
- This is a very common source of confusion. The mental model customers use: "I'm checking if the image attribute is empty." The actual model: "I'm checking if the value that is mapped to that attribute is empty." These point to the same underlying data, but the UI labels don't make it obvious.
- Quick diagnosis: if a customer shows you rules that reference things like "Main image," "Product title," etc. (the WooCommerce field names) but their mapping uses renamed custom fields, the rules are almost certainly referencing the wrong identifier.
