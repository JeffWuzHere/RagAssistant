# Knowledge Base Entry: Rules and filters fail silently when category name contains a space — fixed in v13.4.1.1

## 🎯 Executive Summary
**The Issue:** Rules and filter conditions that reference a WooCommerce category name containing a space (e.g., "Men Shoes", "New Arrivals") failed to match any products, effectively making the rule inoperative.
**The Fix:** This was a confirmed bug fixed in **Product Feed Pro v13.4.1.1**. Updating to v13.4.1.1 or later resolves it.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** rules not matching categories, filter not working for category, category rule failing, include only category not working, category filter no products, rule with category name not applying, space in category name rule broken
>
> **Steps to solve:**
> 1. Confirm the customer's rule/filter references a category name that contains a **space** (e.g., "Men's Shoes", "New Arrivals", "Sale Items").
> 2. Ask them to update **Product Feed Pro to v13.4.1.1 or later**.
> 3. After updating, refresh the feed and verify the rule now correctly includes or excludes the matching category.
> 4. If the customer cannot update immediately, suggest a workaround: rename the category to remove spaces (e.g., "NewArrivals" or "New-Arrivals") — though this impacts the storefront display.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- This bug caused silent failures — the rule appeared to be configured correctly, but matched 0 products, causing "include only" rules to produce empty feeds or "exclude" rules to include all products.
- Category names with special characters (hyphens, apostrophes) may also have been affected — if a customer reports rules not working for categories with any non-alphanumeric characters, v13.4.1.1+ is still the right fix.
