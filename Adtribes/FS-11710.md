# Knowledge Base Entry: Strip HTML tags from custom fields in product feed — custom fields require correct field prefix in snippet

## 🎯 Executive Summary
**The Issue:** Customer wanted to remove `<strong>` tags from a custom field (`product_highlight`) in the feed using a PHP snippet. The snippet worked for `description` but not for custom fields, because custom fields in `$product_data` are stored under a prefixed key, not the bare field name.
**The Fix:** Use the correct prefixed key for custom fields in the snippet (e.g., `custom_attribute_product_highlight` instead of `product_highlight`). Add it to the child theme's `functions.php` using the `adt_get_product_data` hook.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** remove HTML from feed, strip strong tags, custom field HTML not removing, adt_get_product_data snippet not working for custom fields, product_highlight HTML still showing, ACF HTML in feed
>
> **Steps to solve:**
> 1. Identify the field the customer wants to modify. For core WooCommerce fields (`description`, `title`, `price`), use the bare key name. For custom/ACF/meta fields, the key in `$product_data` is prefixed.
> 2. To find the correct key: ask the customer to check the field name as it appears in Product Feed Pro > Settings (after running Clear Custom Attribute Cache) or enable debug logging to dump `$product_data`.
> 3. Use this snippet pattern, adjusting the key and the HTML to strip:
>
> ```php
> add_filter( 'adt_get_product_data', function( $product_data, $feed ) {
>     // For a custom field like 'product_highlight', the key may be prefixed
>     $field_key = 'custom_attribute_product_highlight'; // adjust as needed
>     if ( isset( $product_data[ $field_key ] ) && ! empty( $product_data[ $field_key ] ) ) {
>         $product_data[ $field_key ] = wp_strip_all_tags( $product_data[ $field_key ] );
>         // Or for specific tags only:
>         // $product_data[ $field_key ] = str_replace( array('<strong>', '</strong>'), '', $product_data[ $field_key ] );
>     }
>     return $product_data;
> }, 10, 2 );
> ```
>
> 4. Add to child theme `functions.php` or via WP Code plugin.
> 5. Regenerate the feed and verify via incognito that the HTML tags are no longer present.
> 6. Note: for standard WooCommerce `description` field, Google and most platforms handle `<strong>` and `<li>` fine — removing it is optional.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- Custom field keys in `$product_data` are **not** the same as their database meta keys or their display names in the UI. They carry a prefix that the plugin adds during data collection. The safest way to find the exact key is to temporarily dump `$product_data` via the hook and inspect the output.
- `wp_strip_all_tags()` is cleaner than manual `str_replace()` for stripping all tags; use `str_replace()` only when you need to remove specific tags while preserving others.
- Scope: `adt_get_product_data` runs per-product during feed generation, so this adds minimal server load. It only runs during feed refresh, not on every page load.
