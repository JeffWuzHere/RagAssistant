# Knowledge Base Entry: HTML tags appearing in product descriptions in feed when using UX Builder page builder

## 🎯 Executive Summary
**The Issue:** A customer using UX Builder to create product descriptions found that the feed was outputting HTML tags in the description field, and they were concerned this would affect Google Merchant Center (GMC) security/stability.
**The Fix:** The plugin strips most HTML from descriptions, but some tags may pass through from page builders; certain HTML formatting tags (e.g., `<li>`, `<strong>`) are actually supported by Google — the customer needs to identify which specific tags are showing and determine if they are page-builder structural HTML or supported formatting tags.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** HTML tags in description, page builder descriptions, UX Builder feed description, HTML in GMC feed, description formatting tags, strip HTML descriptions
>
> **Steps to solve:**
> 1. Ask the customer which specific HTML tags are appearing in the feed (e.g., `<li>`, `<strong>`, `<div>`, custom builder markup).
> 2. Explain that the plugin strips HTML from descriptions by default, but page builders often store descriptions with additional markup that may not all be caught.
> 3. If the tags are standard formatting tags (`<li>`, `<strong>`, `<em>`, `<p>`), reassure the customer that Google supports these in descriptions: https://support.google.com/merchants/answer/7052112
> 4. If structural/layout HTML from the page builder is leaking through (e.g., complex `<div>` structures, custom shortcodes), ask for the debug log to investigate the raw description value.
> 5. There is no known GMC "security" risk from HTML in descriptions — the concern is about data quality/disapprovals, not security.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- UX Builder (and similar page builders like Elementor, WPBakery, Divi) store their content in custom post meta or shortcode format rather than in the standard WooCommerce short/long description fields. The plugin may pick up the raw stored value including builder markup.
- Google supports a subset of HTML formatting tags in product descriptions. Structural HTML from page builders is the real concern — not standard formatting tags.
- The correct next diagnostic step is always the debug log to see the raw description value the plugin is reading.
- There is no GMC "security" risk from HTML in descriptions; the risk is item disapproval due to policy violations or formatting issues.
