# Knowledge Base Entry: Feed showing 'not available' — XML file accidentally deleted; fix by duplicating the feed

## 🎯 Executive Summary
**The Issue:** An existing feed that previously worked correctly began showing "Feed not available" with an empty Statistics tab. The underlying XML file had been accidentally deleted (likely by a server cleanup task or hosting provider).
**The Fix:** Duplicate the affected feed, activate the duplicate, refresh it, and update any ad platform integrations with the new XML URL.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** feed not available, feed URL returns 404, feed statistics empty, feed stopped working nothing changed, XML file gone, feed URL broken, feed disappeared
>
> **Steps to solve:**
> 1. Confirm the feed's XML URL returns a 404 or empty response (visit it directly in incognito mode).
> 2. Explain: when the underlying XML file is deleted, the feed will always fail to refresh — it cannot regenerate from a missing file handle.
> 3. **Fix:** Go to the feed list and **Duplicate** the affected feed.
> 4. The duplicated feed will default to **Inactive** — click to activate it.
> 5. Click **Refresh** to generate the XML for the new feed.
> 6. Confirm the new XML URL is working by visiting it in incognito.
> 7. **Update the URL** in any ad platforms (Google Merchant Center, Facebook Catalog, etc.) that were using the old feed URL.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- Once an XML file is deleted, refreshing the original feed will not recreate it — the feed engine cannot regenerate from a missing file reference. Duplication is the only recovery path.
- The new duplicate will have a **new XML filename/URL** — the customer must update all downstream integrations (GMC, Meta, etc.) with the new URL.
- Server-side cleanups (e.g., clearing `/uploads/` or `/wp-content/` subfolders) can accidentally delete feed XML files. If a customer reports feeds disappearing after server maintenance, this is the likely cause.
- After duplication, the copy defaults to Inactive — remind the customer to activate it before refreshing.
