# Knowledge Base Entry: Feed auto-updates failing with "no callbacks" error and Sync Product Feed creating Unknown feeds

## 🎯 Executive Summary
**The Issue:** Feed auto-refresh fails with Action Scheduler error "Scheduled action will not be executed as no callbacks are registered," and running Sync Product Feed creates many blank/Unknown feed entries.
**The Fix:** Duplicate or recreate the affected feed(s). The plugin now uses WooCommerce Scheduled Actions exclusively — not WP-Cron — and "no callbacks" indicates the feed was created with corrupt/incomplete parameters that must be regenerated.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** feeds not auto-refreshing, Action Scheduler "no callbacks" error, Sync Product Feed creating Unknown feeds, feed generation stuck, WP-Cron vs Action Scheduler, feed refresh unstable
>
> **Steps to solve:**
> 1. Check WooCommerce > Status > Scheduled Actions > Failed for the hook `adt_pfp_as_generate_product_feed_batch` or `adt_pfp_as_product_feed_update_stats`. If present, the feed was created with bad parameters.
> 2. **Do not** run Product Feed > Settings > Sync Product Feed without knowing the side effect — it can create many blank "Unknown" feeds. If this has already run and created Unknown entries, refer to the KB article: https://adtribes.io/knowledge-base/how-to-stop-automatic-blank-feed-generation/
> 3. Duplicate the problematic feed or create a new one from scratch. This regenerates all required callbacks and parameters.
> 4. If the customer was using WP-Cron: inform them the plugin migrated away from WP-Cron to WooCommerce Action Scheduler. WP-Cron-triggered refreshes will fail. They should remove any WP-Cron entries for feed hooks and rely solely on the plugin's built-in scheduler.
> 5. After uninstall/reinstall with "clean up plugin data" enabled: manually clear old Action Scheduler job groups. Old AS jobs can persist and interfere with a fresh install.
> 6. On reimport of exported feeds: feeds will be in Inactive status — the customer must click each feed to activate it.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- "No callbacks registered" is a feed-level corruption, not a plugin-level bug. The fix is always to recreate the feed, never to re-register callbacks manually.
- Sync Product Feed is a recovery tool but has a known side effect of generating blank/Unknown feeds if there are legacy DB entries. Use it only when explicitly troubleshooting, and warn the customer in advance.
- The migration from WP-Cron to WooCommerce Action Scheduler is permanent. Any customer still routing refresh triggers through WP-Cron will see silent failures.
- When a customer reports refresh instability after a long exchange (multiple feed recreations, syncs, reinstalls), suspect Action Scheduler job queue pollution — old/orphaned jobs from previous installs can block new ones.
