# Knowledge Base Entry: Mapping WooCommerce core GTIN field — use 'Global Unique ID'; identifier_exists requires Brand + GTIN or Brand + MPN

## 🎯 Executive Summary
**The Issue:** The customer was trying to map WooCommerce's built-in GTIN field (added as a core feature in recent WooCommerce versions) to `g:gtin` in the feed. The field didn't appear to be outputting correctly. Separately, `g:identifier_exists` was being set to "No" even when GTIN was present.
**The Fix:** Use the **"Global Unique ID"** mappable field for the WooCommerce core GTIN. For variable products, GTIN is stored per-variation (not on the parent). The `identifier_exists` = Yes requires **both Brand AND GTIN (or Brand AND MPN)** — having only GTIN is not sufficient.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** WooCommerce GTIN not in feed, core GTIN field not mapping, identifier_exists wrong, identifier_exists No even with GTIN, GTIN field not showing, how to map WooCommerce built-in GTIN, woosea gtin not working
>
> **Steps to solve:**
> 1. For **WooCommerce's native GTIN field** (not Yoast, not ACF, not a custom field): use the **"Global Unique ID"** mappable field in Field Mapping.
> 2. For **variable products**, GTIN is stored per-variation: go to the product editor → **Variations** tab → expand each variation → find the GTIN field. This is separate from the parent-level GTIN in the **Inventory** tab.
> 3. If the `g:identifier_exists` attribute is showing "No" even when GTIN is set:
>    - `identifier_exists` = Yes requires: **Brand** + **GTIN** OR **Brand** + **MPN**
>    - GTIN alone is not sufficient — the Brand field must also be populated and mapped.
>    - Enable "Add GTIN, MPN, etc." in **Product Feed Elite > Settings**, then map the Brand field in the feed.
> 4. If the feed appears to not pick up GTIN values after correct mapping, try clearing the site/server cache — cached product data can cause stale output.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- WooCommerce added a native GTIN field in recent versions. The "Global Unique ID" mappable field in Product Feed Pro/Elite reads from this native field.
- "woosea gtin 1" or similar ACF/Yoast field names are for third-party GTIN plugins. If the customer is using the WooCommerce core field, only "Global Unique ID" will work.
- The `identifier_exists` logic in the plugin: it's set to "Yes" only if the product has a Brand AND at least one of GTIN or MPN. See Google's spec: https://support.google.com/merchants/answer/6324478
- Variable product GTIN is always at the variation level, not the parent level. If a customer says "GTIN is set but not appearing for variants," check if they entered it on the parent's Inventory tab (wrong) vs. each variation (correct).
- Server/object cache can cause newly-entered GTIN values to not appear in feed output. Clearing cache is a valid first step when mapping is correct but values are missing.
