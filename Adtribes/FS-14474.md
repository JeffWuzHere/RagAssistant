# Knowledge Base Entry: Feed doubles in product count when enabling default variation option

## 🎯 Executive Summary
**The Issue:** A customer followed the KB article to include only one variation per product in a feed, but the feed doubled in product count (from ~520 to ~1,100 products) in both Google Merchant and Pinterest.
**The Fix:** WP Rocket caching was serving a stale cached version of the XML feed; disabling WP Rocket caching for the plugin or excluding the feed URLs from caching resolved the doubled product count.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** feed showing double products, product count doubled, variations duplicated in feed, Google Merchant showing double, Pinterest showing double, WP Rocket and product feed
>
> **Steps to solve:**
> 1. Confirm the feed config has **"Add default variations only"** toggle enabled and the product's **"Default variation"** is set.
> 2. Ask the customer to create a brand-new feed and view the XML file via **incognito mode** to bypass any browser/server cache.
> 3. If the new feed in incognito still shows doubled products, troubleshoot the feed filter/rule settings.
> 4. If the new feed looks correct in incognito but the channel (Google Merchant, Pinterest) shows doubled counts, the issue is **WP Rocket caching** serving a stale XML.
> 5. Disable WP Rocket for the AdTribes plugin or exclude the feed URLs from WP Rocket's cache. Point customer to WP Rocket's exclusion docs and suggest contacting WP Rocket support for guidance.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- The doubled product count on channel dashboards (while the feed XML itself is correct) is a strong indicator of WP Rocket or another caching plugin serving a stale copy of the feed.
- Always test with a fresh feed in incognito as the first diagnostic step — if that looks correct, the problem is almost always a caching layer, not a plugin logic error.
- The KB article referenced covers adding only one variation; the expected product count after enabling it should be simple products + one variation per variable product (not all variations).
