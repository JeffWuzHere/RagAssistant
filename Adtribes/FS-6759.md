# Knowledge Base Entry: Variable product feed showing variation image instead of parent featured image — use 'Main image simple and variations'

## 🎯 Executive Summary
**The Issue:** For variable products in a Facebook Catalog feed, the feed was pulling either the variation-specific image or the parent product gallery image instead of the parent product's featured image.
**The Fix:** Map the `image_link` attribute to the **"Main image simple and variations"** mappable field, which consistently uses the parent product's featured image for all variations.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** variable product wrong image, variation image in feed, parent image not showing, featured image not used, feed using variation image instead of product image, image_link wrong product, Facebook catalog image issue
>
> **Steps to solve:**
> 1. Open the feed and go to the **Field Mapping** tab.
> 2. Find the `image_link` (or `g:image_link`) attribute row.
> 3. Change the mapped field to **"Main image simple and variations"**.
> 4. Save the settings and refresh the feed.
> 5. Open the XML/CSV in incognito and verify that variation rows now show the parent product's featured image URL.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- "Main image simple and variations" specifically resolves this because it reads the featured image from the **parent** product for all variation rows, ignoring variation-level images.
- If the customer has set variation-specific images in WooCommerce and wants those used instead (not the parent), they should use the default "Image" or "Main image" field.
- This mappable field name is available for both Google Shopping and Facebook/Meta feed templates.
- The fix applies equally to Google Shopping feeds that show wrong images for variable products.
