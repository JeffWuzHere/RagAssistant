# Knowledge Base Entry: Feed perpetually generating empty copies — orphaned pending Action Scheduler entry; also store_code numbers-only bug and out_of_stock value format

## 🎯 Executive Summary
**The Issue:** Multiple overlapping problems: (1) The feed kept creating new empty feed files every hour due to an orphaned "Pending" scheduled action that had no corresponding active feed. (2) The `store_code` attribute wasn't outputting correctly when the value contained only numbers — a known bug. (3) A rule to exclude out-of-stock products wasn't working because `out of stock` (with space) was used instead of `out_of_stock` (with underscore).
**The Fix:** (1) Delete the orphaned pending action from WooCommerce > Status > Scheduled Actions > Pending. (2) A hotfix was provided for the store_code bug (numbers-only values). (3) Change the availability rule value to `out_of_stock` (underscore, no spaces).

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** feed creating empty files every day, blank feeds being generated, duplicate empty feeds, store_code not outputting, store code missing from feed, local product feed store code bug, out of stock products still in feed, availability rule not working, exclude out of stock not working
>
> **Steps to solve:**
> **Issue 1 — Orphaned pending scheduled action creating empty feeds:**
> 1. Go to **WooCommerce > Status > Scheduled Actions > Pending**.
> 2. Search for pending actions with the name `pfp` or `feed` (or `adt_pfp_as_generate_product_feed`).
> 3. Identify any pending action whose feed ID does not match any of your current active feeds. (Find a feed's ID by editing it and checking the URL parameter.)
> 4. Delete the orphaned pending action(s).
> 5. Go to **Product Feed > Settings** and run the **Remove Duplicate/Empty Feeds** tool to clean up the already-generated empty files.
>
> **Issue 2 — store_code not outputting when value is numbers-only:**
> 1. This was a known bug — `store_code` values that contain only numbers (e.g., `12345`) were not being output in the feed XML.
> 2. Update the plugin to the latest version — the fix was included in a subsequent release.
> 3. If the customer is on an older version and the fix hasn't shipped yet, the workaround is to prefix the store code with a letter (e.g., `S12345`) if the platform allows it.
>
> **Issue 3 — Availability rule not excluding out-of-stock products:**
> 1. When creating a rule/filter to exclude out-of-stock products, the value must be exactly: `out_of_stock` (underscore between the two words).
> 2. Using `out of stock` (with a space) will not match and the rule will silently fail.
> 3. Correct rule: `Availability` `is equal to` `out_of_stock` → Action: Exclude.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- The orphaned pending action pattern occurs when a feed is deleted or deactivated but its corresponding scheduled action wasn't cleaned up. The Action Scheduler keeps firing the job, which creates empty feed files since the feed no longer exists. The fix: always delete orphaned pending actions manually.
- The `store_code` numbers-only bug was raised as a GitHub issue and fixed in a subsequent release. Customers using Google Local Product Inventory feeds with numeric store codes will see "Missing inventory data" in GMC until they update.
- The `out_of_stock` underscore requirement is not documented prominently. Support agents should proactively check rule values when a customer says their availability exclusion rules aren't working.
- These three issues are completely independent — they happened to occur on the same site simultaneously. Don't conflate them when diagnosing.
