# Knowledge Base Entry: Change g:product_type category path separator from || to > using a code snippet

## 🎯 Executive Summary
**The Issue:** The `g:product_type` field in Google Shopping XML feeds outputs category paths using `||` as the separator (e.g., `Clothing || Shirts || Men`) instead of the `>` separator required by Google's spec.
**The Fix:** Add a custom snippet using the `adt_product_feed_xml_attribute_value` filter to replace `||` with `>` in the `g:product_type` field at output time.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** product_type separator, category path separator wrong, || in product_type, change separator to >, g:product_type format Google Shopping
>
> **Steps to solve:**
> 1. Ask the customer to add the following snippet to their child theme's `functions.php` or via the **WP Code** plugin:
> ```php
> add_filter( 'adt_product_feed_xml_attribute_value', 'change_product_type_separator_in_xml', 10, 5 );
> function change_product_type_separator_in_xml( $v, $k, $product, $value, $feed ) {
>     if ( strtolower( $k ) === 'g:product_type' || strtolower( $k ) === 'product_type' ) {
>         $v = str_replace( '||', '>', $v );
>         $v = str_replace( ' || ', ' > ', $v );
>         $v = str_replace( '|| ', '> ', $v );
>         $v = str_replace( ' ||', ' >', $v );
>     }
>     return $v;
> }
> ```
> 2. After adding the snippet, refresh the feed.
> 3. Verify the XML output — `g:product_type` values should now use `>` as the separator.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- The `adt_product_feed_xml_attribute_value` filter receives `$v` (the current value), `$k` (the attribute key name), `$product`, `$value`, and `$feed`. It is the correct hook for modifying individual XML attribute values at output time.
- The snippet checks for both `g:product_type` and `product_type` (case-insensitive) to handle both naming conventions.
- Multiple `str_replace` calls handle edge cases where the `||` separator may or may not have surrounding spaces.
- This is a cosmetic fix only — Google accepts both `||` and `>` as separators, but the customer may have a platform or downstream requirement for `>`.
