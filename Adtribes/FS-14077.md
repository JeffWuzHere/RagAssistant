# Knowledge Base Entry: Feed only outputs one category path — workaround for products in multiple category trees

## 🎯 Executive Summary
**The Issue:** Products assigned to multiple WooCommerce category trees (e.g., `Men > Shoes > Sneakers` AND `Offers > Shoes`) only output one path when `category_path` is mapped to `product_type`. The "Category (comma-separated)" option loses the hierarchy separators.
**The Fix:** Manually create custom product fields for each additional category path, then map them as `product_type` in the feed. Google Shopping supports up to 5 `product_type` entries per product.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** multiple category paths in feed, product_type with multiple trees, all categories in feed, second category path missing, product assigned to multiple categories only one showing
>
> **Steps to solve:**
> 1. Explain the current limitation: `category_path` only outputs the first/primary category path. The plugin selects the first path from the product's category assignments.
> 2. **Workaround for multiple category paths:**
>    - Create custom product fields (e.g., via ACF or a custom meta field) for each additional category path. Name them `category_path_2`, `category_path_3`, etc.
>    - Manually set the full hierarchy path (e.g., `Offers > Shoes`) in these custom fields for each product.
>    - In the feed's Field Mapping, add additional `product_type` rows and map each to the corresponding custom field.
> 3. Google Shopping supports up to 5 `product_type` values per product — repeat the mapping up to 5 times.
> 4. Note: Google's GMC does NOT support comma-separated `product_type` values in a single field. Each must be a separate attribute entry.
> 5. Raise as a feature request if the customer wants native multi-tree support.

**[SUPPORT_AGENT]:**
Confirmed: multi-tree category path mapping is not currently supported. The plugin always outputs the first category path. Raised a feature request. Workaround: create custom fields for additional category paths and set the values manually per product, then map each custom field to a separate `product_type` row in the feed.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- This is a known limitation. The plugin selects the "first" category path, which may be alphabetical or based on category ID order — not necessarily the most relevant one for the customer's use case.
- The workaround requires manual data entry per product, which is only practical for small catalogs. For large catalogs, this is not a viable solution — the feature request is the right answer.
- Google's GMC does not accept comma-separated product_type in a single field. Each additional path must be a separate `product_type` attribute row.
