# Knowledge Base Entry: Exclude a specific shipping zone/rate from the product feed to fix inaccurate shipping cost errors in GMC

## 🎯 Executive Summary
**The Issue:** Google Shopping flagged shipping as inaccurate because a regional shipping zone (Northern Ireland, postcode BT*) was cheaper than the main UK zone, and both were being included in the feed.
**The Fix:** Add a PHP snippet using the `adt_product_feed_shipping_array` filter to exclude the specific shipping rate by its WooCommerce rate ID. The key is to `return false` (not `return array()`) to properly remove the entry.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** inaccurate shipping cost errors in Google Merchant Center, exclude shipping zone from feed, remove specific shipping method from product feed, shipping rate mismatch between feed and website
>
> **Steps to solve:**
> 1. Identify the WooCommerce rate ID to exclude. The format is `method_id:instance_id` (e.g., `betrs_shipping:22-2`). The customer can find this by checking WooCommerce > Settings > Shipping or by enabling debug logging and inspecting the rate IDs in the feed.
> 2. Add the following snippet to the child theme's `functions.php` or via the WP Code plugin:
>
> ```php
> add_filter( 'adt_product_feed_shipping_array', function ( $shipping, $rate, $feed, $package ) {
>     $exclude_rate_ids = array( 'betrs_shipping:22-2' ); // Replace with your rate ID(s)
>     if ( in_array( $rate->get_id(), $exclude_rate_ids, true ) ) {
>         return false; // Must return false, not array()
>     }
>     return $shipping;
> }, 10, 4 );
>
> add_filter( 'adt_product_feed_shipping_data', function ( $shipping_data, $product, $feed ) {
>     return array_values( array_filter( $shipping_data ) );
> }, 20, 3 );
> ```
>
> 3. Regenerate the feed and verify via incognito that the excluded shipping rate no longer appears in the XML.
> 4. Resync with Google Merchant Center.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- The original snippet from the agent used `return array()` which does NOT work — the filter chain still processes the empty array and includes a blank shipping entry. The correct fix is `return false`, which the `array_filter` call on the second filter then strips out.
- The second filter (`adt_product_feed_shipping_data`) with `array_values(array_filter(...))` is required to clean up the resulting array after `false` values are removed.
- To find the exact WooCommerce rate ID for any shipping method, enable debug logging or ask the customer to check WooCommerce > Settings > Shipping and note the method/instance IDs.
