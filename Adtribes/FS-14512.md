# Knowledge Base Entry: Feed generation failing — batch_size not persisting in adt_product_feed object

## 🎯 Executive Summary
**The Issue:** A customer with a large catalog (~7,862 products) reported feed generation failing because the `batch_size` value was showing as `0` in the `adt_product_feed` object despite being set to 200 in plugin settings, causing timeouts or memory exhaustion.
**The Fix:** Support could not be extended without license verification; customer was directed to verify their license, check WooCommerce > Status > Logs, and review failed scheduled actions for error details.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** batch size not saving, batch_size showing 0 in logs, feed stuck in error status, feed generation timeout, memory exhaustion with large catalog, adt_product_feed batch_size
>
> **Steps to solve:**
> 1. Verify the customer's license key before providing extended support — unverified customers should be pointed to the WordPress.org support forum.
> 2. Ask the customer to go to **WooCommerce > Status > Logs** and share any critical error logs related to the feed.
> 3. Ask them to check **WooCommerce > Status > Scheduled Actions** and look at failed action schedulers for information about why feed processing stopped.
> 4. If `batch_size` is genuinely not persisting in the `adt_product_feed` post meta, this may be a plugin bug — escalate to development and reference the environment: PHP 8.4, WooCommerce 10.7.0, plugin 13.5.3.
> 5. Ask the customer to clear the object cache and try re-saving feed settings, then confirm the value is written to the database.
