# Knowledge Base Entry: Feed outputting prices without VAT — WooCommerce tax rates set to 0 for affected countries; fix WC tax settings or use multiply rules

## 🎯 Executive Summary
**The Issue:** A WPML multi-country store's feed was outputting prices without VAT. The customer expected VAT-inclusive prices but the feed XML showed lower prices. The root cause: WooCommerce tax rates for the affected countries were configured as 0%, so the plugin correctly applied no tax.
**The Fix:** Add correct tax rates in **WooCommerce > Settings > Tax** for the affected countries. Alternatively, use the Rules feature to multiply the price by the appropriate VAT multiplier (e.g., ×1.23 for 23% VAT) per product category or tax class.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** feed prices without VAT, prices lower than expected in feed, VAT not included in feed price, feed not including tax, prices missing tax, wrong price in feed multi-country, WPML feed price too low
>
> **Steps to solve:**
> 1. Ask the customer to go to **WooCommerce > Settings > Tax** and check the configured tax rates for the countries where prices are appearing without VAT.
> 2. If the tax rates are set to 0 (or missing) for those countries, this is the root cause — the plugin reads WooCommerce tax configuration directly.
> 3. **Preferred fix:** Add the correct tax rates in WooCommerce for each affected country. Once saved, refresh the feed — prices will now include the correct VAT.
> 4. **Workaround (if WC tax settings can't be changed):** Use the feed's Rules feature. Add a rule per VAT band: "If [category/tax class] contains [X], then [price field] multiply by [1 + VAT rate]." For example, 23% VAT = multiply by 1.23.
> 5. Note: the multiply-rule workaround introduces minor rounding differences (up to 1 cent) due to floating-point arithmetic. If precision is critical, configure WooCommerce tax rates instead.
> 6. Also check **Product Feed Elite > Settings** — if the **Exclude Tax** option is enabled, disable it, as this forces tax-exclusive prices regardless of WooCommerce tax settings.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- The plugin reads WooCommerce's computed product price, which already factors in the configured tax rates. If WooCommerce has 0% tax for a country, the feed will output the base price with no addition — this is correct behavior, not a bug.
- This scenario is common in stores with multi-country/WPML setups where the admin configured tax rates for domestic markets but left international rates at 0 (or unset). The store frontend may show prices differently due to frontend tax display settings, creating a perceived mismatch.
- The multiply-rule workaround produces prices within 1 cent of the correct value due to floating-point rounding. For advertising feeds where exact price matching matters (GMC price mismatch policy), fixing the WooCommerce tax rates is strongly preferred over the rules workaround.
- See also FS-6998 for a different cause of missing VAT: "System Price" field fix when WooCommerce tax IS configured but the standard Price field isn't picking it up correctly.
