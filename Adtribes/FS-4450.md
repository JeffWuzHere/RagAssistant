# Knowledge Base Entry: WPML feed outputting higher prices for products with non-standard tax classes — use System Price as workaround

## 🎯 Executive Summary
**The Issue:** Feeds using WPML were outputting prices higher than the actual store prices for products assigned to a custom (non-standard) tax class (e.g., a reduced 5% VAT rate). Products on the standard tax class were unaffected.
**The Fix:** Use the **"System Price"** mappable field as a workaround. The underlying bug — tax options not being properly respected for custom tax classes — was confirmed and raised with the development team (GitHub issue #243).

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** WPML feed higher prices, prices wrong in feed with WPML, reduced tax class wrong price, custom tax class inflated price in feed, 5% VAT wrong price feed, non-standard tax rate price mismatch, feed price doesn't match store price WPML
>
> **Steps to solve:**
> 1. Confirm the pattern: products on the **standard tax class** show correct prices; products on a **custom or reduced tax class** show inflated prices (e.g., price calculated as if standard 23% VAT applies instead of the product's actual 5% rate).
> 2. This is a confirmed plugin bug — the price calculation doesn't properly respect custom tax classes when WPML is active.
> 3. **Workaround:** In the feed's Field Mapping, change the price attribute from the current price field to **"System Price"**.
> 4. Save and refresh the feed. Verify the prices now match the frontend for products with custom tax classes.
> 5. Note: a permanent fix has been raised with the development team. If the customer is on a newer plugin version and the issue is still present, check the GitHub issue status: https://github.com/Rymera-Web-Co/woo-product-feed-elite/issues/243

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- The bug is specific to the combination of WPML + custom/non-standard tax classes. Without WPML, or with only the standard tax class, prices are calculated correctly.
- A competitor plugin outputting the correct price for the same product is strong evidence that the issue is in AdTribes' tax class handling, not in the WooCommerce tax configuration itself.
- "System Price" bypasses the plugin's internal price calculation and reads the price directly from WooCommerce's computed value — which does correctly apply the tax class. This is why it works as a workaround.
- Customers with stores selling products at mixed tax rates (standard + one or more reduced rates) are the most likely to encounter this. Stores with only standard-rate products will never see it.
