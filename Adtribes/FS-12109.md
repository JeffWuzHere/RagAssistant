# Knowledge Base Entry: GTINs appearing as scientific notation (E+11) in feed XML — browser rendering issue, not a plugin bug

## 🎯 Executive Summary
**The Issue:** After updating to v5.0.6 / v13.5.2, a customer reported that numeric-only GTINs were displaying in scientific notation (e.g., `1.23456789012E+11`) in the feed XML. The GTIN data was saved correctly in WooCommerce.
**The Fix:** This is a browser rendering issue — some browsers (Firefox, Edge in reader mode) display large integers in XML view as scientific notation. The actual feed data is stored correctly. Verify by opening the XML in Chrome or checking the product directly in Google Merchant Center.

---

## 🛠 Final Resolution (The "2nd Me" Guide)
> [!TIP]
> **Use this solution if a customer asks about:** GTIN scientific notation, GTIN E+11 in feed, GTIN showing wrong format, numeric GTIN displaying as exponential, large number GTIN feed error, GTIN converted to E notation after update
>
> **Steps to solve:**
> 1. Ask the customer to open their feed XML in **Chrome** (not Firefox, Edge, or Safari). Large integers are sometimes rendered in scientific notation by certain XML viewers even when the underlying value is correct.
> 2. In Chrome, verify that the GTIN appears as a full 13-digit (or relevant length) number, not exponential notation.
> 3. If Chrome shows the correct value, the data is fine — there is no plugin bug. Advise the customer to check the product directly in **Google Merchant Center** to confirm GMC is receiving the correct GTIN.
> 4. If the GTIN is also wrong in GMC, then the issue is in the data itself (e.g., GTIN stored as a float in the database, truncated when saved). In that case, verify the raw GTIN value in the product edit screen and re-save.

## 💡 Internal Insights (If applicable)
*This section contains logic extracted from internal notes or agent-to-agent talk.*
- Browsers like Firefox render large integers in XML views as scientific notation for display purposes. The raw XML file content is not affected — if you download and open the file in a text editor, the full number will appear.
- This misdiagnosis is very common after updates because customers assume new behavior = new bug. In this case, the customer may have simply started viewing their XML in a different browser.
- The practical confirmation test: if the product passes GMC validation with the correct GTIN, the plugin data is fine regardless of what the browser XML view shows.
- GTINs must be stored as strings (not numbers) in WooCommerce to prevent floating-point precision issues. If the GTIN is somehow being stored as a numeric type, re-saving the product should force it to string.
